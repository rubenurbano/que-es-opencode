OpenCode 2.0 · Tutorial

¿Qué es OpenCode?

OpenCode es un agente de programación con inteligencia artificial de código abierto. Le escribes en lenguaje normal lo que quieres, y el agente puede leer los archivos de tu proyecto, proponer cambios, escribirlos y ejecutar comandos, siempre dentro de los permisos que tú le des.

Analogía. Imagina que contratas a un ayudante muy rápido en tu taller. Le dices «arregla la puerta del armario». Puede mirar el armario, buscar herramientas, proponer la reparación y hacerla. Pero si no le pones límites, también podría tocar cosas que no querías. Los permisos son esos límites.

⚠️ Aviso importante: existen OpenCode 1 y OpenCode 2. Comparten el mismo comando opencode, pero tienen diferencias en configuración y plugins. Este tutorial documenta la versión 2 (paquete @opencode/cli, versión 2.0.32 en el registro npm). Si un tutorial antiguo usa permission, bash o task, es de la V1: en la V2 se llaman permissions, shell y subagent.

Cómo usar este tutorial

Este tutorial está pensado para leerse en orden, aunque cada pestaña se entiende por separado. Sigue esta ruta:

  1. CONCEPTOS: entiende el vocabulario antes de tocar nada.
  2. PROCEDIMIENTO: instala, conecta y configura paso a paso.
  3. PRÁCTICA: haz los ejercicios con prompts listos para copiar.
  4. ERRORES: consulta cuando algo falle.
  5. RESUMEN: repasa y autoevalúate.
💡 Etiquetas de fiabilidad. A lo largo del tutorial verás PROBADO para lo que se ejecutó realmente en el entorno de redacción, DOCUMENTADO para lo que solo consta en la documentación oficial, y texto sin etiqueta para conocimiento general no verificado.

Qué vas a aprender

  • Instalar OpenCode y comprobar que funciona.
  • Conectar un proveedor de IA y elegir un modelo.
  • Pedir tareas con claridad y revisar lo que el agente hace.
  • Configurar permisos prudentes.
  • Guardar versiones con Git y deshacer cambios.
  • Crear una página web, corregir errores con pruebas y controlar costes.

Chat de IA frente a agente de programación

Un chat de IA solo ve lo que tú pegas en la conversación. Un agente como OpenCode puede leer tus archivos y actuar sobre ellos.

Qué haceResponde con textoLee, busca, edita, crea y ejecuta comandos
Quién aplica los cambiosTú, copiando y pegandoEl agente, con tu aprobación según permisos
Riesgo principalRespuestas incorrectasRespuestas incorrectas y acciones reales en tu ordenador

Modelo, proveedor y clave API

  • Modelo: el «cerebro» de IA que genera las respuestas.
  • Proveedor: la empresa o servicio que ofrece el modelo (Anthropic, OpenAI, etc.). El proveedor es la «tienda»; el modelo, el «producto».
  • Clave API: la contraseña secreta de tu cuenta con un proveedor. Como la llave de tu casa: quien la tenga puede gastar tu saldo.
  • Token: trozo de texto que el modelo procesa. Los proveedores cobran y limitan por tokens.
  • Ventana de contexto: cantidad máxima de tokens que el modelo puede tener presentes a la vez.
⚠️ Nunca compartas tu clave API ni la escribas en archivos que vayas a subir a GitHub o en capturas de pantalla. Si se expone, revócala y crea otra.

Permisos: los límites del agente

Un permiso es una regla que dice si el agente puede (allow), debe preguntar (ask) o tiene prohibido (deny) hacer algo. Cada regla tiene una acción (qué herramienta), un recurso (sobre qué) y un efecto.

⚠️ Advertencia clave. En la V2, un agente nuevo parte de una política base que permite todo salvo la lectura de archivos .env (que pide confirmación). Es decir: por defecto, el agente build no te pregunta antes de editar archivos ni de ejecutar comandos. Aprenderás a cambiarlo en PROCEDIMIENTO.

Regla de oro: si varias reglas coinciden, gana la última. Por eso lo general va primero y las excepciones después.

Paso 1 · Comprueba lo que ya tienes

Objetivo: saber si tienes Node.js, npm y Git antes de instalar.

Abre una terminal y ejecuta estos comandos uno por uno. Si aparece un número de versión, está instalado; si aparece «comando no reconocido», no lo está.

node --version
npm --version
git --version

Resultado esperado: algo como v22.22.2 para Node y 10.9.7 para npm. PROBADO

Si falta algo: instala Node.js desde su web oficial. Git lo necesitarás más adelante para guardar versiones.

Paso 2 · Instala OpenCode

Objetivo: instalar el cliente opencode en tu equipo.

Requisito: Node.js y npm instalados (paso 1).

Ejecuta en la terminal:

npm install -g @opencode/cli

Por qué funciona: npm descarga el paquete y un script elige el binario nativo de tu sistema. Además se crea un comando extra llamado opencode2.

⚠️ Windows: los gestores de paquetes de Windows (Chocolatey, Scoop) no están soportados en la V2. Usa npm, el binario independiente, el instalador de escritorio o WSL. Si npm falla con «la ejecución de scripts está deshabilitada», es un problema de PowerShell, no de OpenCode.

Alternativa: script oficial (macOS y Linux)

curl -fsSL https://opencode.ai/v2/install | bash
⚠️ Seguridad. curl ... | bash ejecuta código remoto con tus permisos. Úsalo solo con la dirección oficial escrita a mano. Si prefieres revisar antes, descarga el script, léelo y ejecútalo después.

Paso 3 · Verifica la instalación

Cierra y abre la terminal (para que se refresque el PATH) y ejecuta:

opencode --version
opencode --help
opencode debug paths

Resultado esperado: opencode v2.0.32 o superior. El comando debug paths muestra dónde están tus datos, configuración y registros. PROBADO

Si dice opencode 1.x: tienes la V1. Desinstálala antes de continuar, porque las dos no conviven bien.

Paso 4 · Conecta un proveedor

Objetivo: guardar tus credenciales y elegir un modelo.

Dentro de la interfaz de OpenCode (ejecuta opencode en una carpeta), escribe estos comandos:

/connect
/models

Qué ocurre: /connect lista los proveedores disponibles; eliges uno y sigues las indicaciones (pegar clave, OAuth…). /models te deja elegir un modelo para la sesión actual.

Verificación: desde la terminal, ejecuta opencode auth list y comprueba que aparece tu proveedor. PROBADO (sin conexiones responde «No authenticated integrations»).

💡 Claves fuera de tus proyectos. Usa /connect: guarda las credenciales en la base de datos del servidor, no en archivos del proyecto. Si prefieres usar variables de entorno, escribe {env:NOMBRE} en la configuración en lugar de la clave.

Paso 5 · Primera conversación segura

Objetivo: hacer una pregunta inofensiva y aprender a rechazar permisos.

Crea una carpeta de práctica y abre OpenCode dentro:

mkdir curso-opencode
cd curso-opencode
opencode

Pega este prompt en el cuadro de texto y pulsa Enter:

Estoy aprendiendo. Explícame en lenguaje sencillo qué es una carpeta de proyecto y qué podrías hacer tú dentro de ella. No crees, edites ni borres ningún archivo, y no ejecutes ningún comando.

Si aparece una petición de permiso: léela y elige Reject (rechazar) si no la entiendes. Las opciones documentadas son: permitir una vez, permitir siempre y rechazar.

Verificación: sal de OpenCode y ejecuta ls (o dir) en la carpeta. No debe haber archivos nuevos.

Paso 6 · Configura permisos prudentes

Objetivo: que el agente pregunte antes de editar y de ejecutar comandos, y que no pueda subir cambios ni leer tus claves.

Crea en tu carpeta un archivo llamado exactamente opencode.jsonc y pega esto:

{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
    { "action": "edit", "resource": "*", "effect": "ask" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
    { "action": "read", "resource": "*.env.*", "effect": "deny" },
    { "action": "external_directory", "resource": "*", "effect": "ask" }
  ]
}

Por qué funciona: las reglas se combinan en orden y gana la última coincidencia. Por eso el ask general va antes que las excepciones.

Verificación: ejecuta opencode debug config y comprueba que tu archivo aparece listado. PROBADO

⚠️ Si tu configuración «no hace nada». Lo primero que debes sospechar es que el archivo no se ha leído por un error de formato. Una coma mal puesta hace que OpenCode lo ignore en silencio. PROBADO

Paso 7 · Instrucciones permanentes con AGENTS.md

Objetivo: darle a OpenCode reglas fijas del proyecto sin repetirlas cada vez.

Crea en la raíz de tu proyecto un archivo llamado exactamente AGENTS.md con este contenido:

# Instrucciones del proyecto: Mi Web

## Qué es este proyecto
Sitio web estático de presentación personal (HTML, CSS y JavaScript).

## Cómo comprobar que funciona
- Abrir `index.html` en el navegador.
- Si existen pruebas: `node --test`.

## Reglas de trabajo
- Pide confirmación antes de borrar archivos o instalar dependencias.
- No toques archivos fuera de este proyecto.
- Explica en lenguaje sencillo cada cambio que hagas.
- Tras cada cambio, indica cómo puedo verificarlo.

## Restricciones
- No leas ni muestres archivos `.env` ni claves.
- No hagas `git push` ni `git commit` salvo que yo lo pida.

Verificación: abre una sesión nueva y pregunta: «¿Qué instrucciones del proyecto tienes en cuenta?».

Importante: la V2 reconoce solo AGENTS.md. No usa CLAUDE.md como alternativa. OpenCode combina varios AGENTS.md sin resolver conflictos: evita reglas contradictorias.

Paso 8 · Guarda versiones con Git

Objetivo: tener un punto de retorno antes de pedir cambios grandes.

Dentro de la carpeta del proyecto:

git -c init.defaultBranch=main init
git config user.name "Tu Nombre"
git config user.email "tucorreo@ejemplo.com"
git add .
git commit -m "Estado inicial"
git log --oneline

Resultado esperado: una línea con el mensaje «Estado inicial». PROBADO

Protege tus secretos. Crea un archivo .gitignore con:

.env
node_modules/
⚠️ Si subes una clave a GitHub por error, considérala robada. Revócala y crea otra. Borrar el archivo después no basta: el historial la conserva.

Ejercicio 1 · Primera conversación sin tocar nada

Objetivo: comprobar que sabes abrir OpenCode, elegir modelo y rechazar permisos.

Requisitos: OpenCode instalado, proveedor conectado, carpeta curso-opencode vacía.

  1. Entra en la carpeta y ejecuta opencode.
  2. Escribe /connect y conecta tu proveedor.
  3. Escribe /models y elige un modelo.
  4. Pega el prompt de abajo.
  5. Si aparece un permiso que no entiendes, elige Reject.
  6. Sal y comprueba con ls que no hay archivos nuevos.
Explícame en lenguaje sencillo qué puedes hacer dentro de esta carpeta vacía y qué cosas te impediría hacer el sistema de permisos. No crees, edites ni borres nada y no ejecutes comandos.

Ejercicio 2 · Crea una página web

Objetivo: crear una web estática de una sola página con HTML, CSS y JavaScript, sin frameworks.

Requisitos: carpeta nueva con Git iniciado, permisos prudentes configurados.

  1. Cambia al agente plan (Shift+Tab).
  2. Pega el prompt de planificación.
  3. Lee el plan. Si te convence, cambia a build y escribe «Adelante».
  4. Revisa los archivos con git status --short.
  5. Abre index.html en el navegador y prueba menú y formulario.
Quiero una web estática de una sola página llamada «Aula Verde» (talleres de jardinería urbana para principiantes). Debe tener: cabecera con menú que se despliegue en móvil, una portada con un botón, una sección de tres talleres en tarjetas, un formulario de contacto con nombre y correo, y un pie de página. Usa solo HTML, CSS y JavaScript, sin frameworks ni librerías externas, y con tres archivos: index.html, styles.css y script.js. Debe verse bien en móvil y en ordenador y ser accesible con teclado. Antes de crear nada, propón un plan y dime cómo comprobaré que funciona. No instales nada.
💡 Verificación mínima: el menú se abre y se cierra; el formulario vacío muestra un aviso; el formulario válido saluda y vacía los campos; puedes recorrer la página con Tab.

Ejercicio 3 · Corrige un error con pruebas

Objetivo: reproducir un fallo, entenderlo, corregirlo y demostrar que está corregido.

Requisitos: Node.js instalado; carpeta mini-tienda con dos archivos: calc.js y calc.test.js.

Crea calc.js con este contenido (tiene un error a propósito):

// calc.js: cálculos de precios de la tienda

// Aplica un descuento en porcentaje. Ejemplo: aplicarDescuento(200, 10) debe dar 180.
function aplicarDescuento(precio, porcentaje) {
  return precio - porcentaje; // <- error a propósito
}

// Suma el IVA (por defecto 21 %).
function totalConIva(precio, iva = 21) {
  return Math.round(precio * (1 + iva / 100) * 100) / 100;
}

module.exports = { aplicarDescuento, totalConIva };

Crea calc.test.js con este contenido:

const test = require('node:test');
const assert = require('node:assert');
const { aplicarDescuento, totalConIva } = require('./calc');

test('un 10 % de descuento sobre 200 da 180', () => {
  assert.strictEqual(aplicarDescuento(200, 10), 180);
});

test('un 0 % de descuento no cambia el precio', () => {
  assert.strictEqual(aplicarDescuento(50, 0), 50);
});

test('el IVA del 21 % sobre 100 da 121', () => {
  assert.strictEqual(totalConIva(100), 121);
});

Ejecuta las pruebas:

node --test

Resultado esperado: 2 pruebas pasan y 1 falla. PROBADO

Pide al agente en modo plan que investigue sin editar:

En esta carpeta ejecuto «node --test» y falla la prueba «un 10 % de descuento sobre 200 da 180». No edites nada todavía. Lee calc.js y calc.test.js, explícame con palabras sencillas por qué falla, formula al menos dos hipótesis y dime cómo confirmarías cada una.

Después, en modo build, pide la corrección con verificación:

Corrige solo la función aplicarDescuento en calc.js para que aplique el porcentaje (precio por (1 menos porcentaje entre 100)), redondeando a dos decimales. No cambies calc.test.js. Después ejecuta «node --test» y muéstrame la salida real.

Verificación final: ejecuta tú node --test y comprueba # pass 3 y # fail 0. PROBADO

⚠️ Trampa frecuente: el agente «arregla» editando la prueba para que pase. Prohíbe tocar el archivo de pruebas y ejecuta tú la comprobación.

Advertencias que no debes ignorar

⚠️ --auto. El indicador --auto aprueba sin preguntar todo lo que no hayas denegado expresamente. No lo uses mientras estás aprendiendo. PROBADO (aparece en la ayuda).
⚠️ Deshacer no lo arregla todo. /undo solo restaura archivos si el proyecto es un repositorio Git y solo en el directorio activo. No deshace efectos de comandos (servicios, bases de datos, commits). Las instantáneas son una comodidad, no una copia de seguridad.
⚠️ El agente puede afirmar que algo funciona sin haberlo probado. Pide siempre la salida real de la prueba y ejecútala tú.

Cómo recuperarte paso a paso

  1. Si la configuración no se aplica: ejecuta opencode debug config y comprueba si tu archivo aparece como documento.
  2. Si no aparece: revisa comas, llaves y comillas rectas.
  3. Vuelve a una versión simple y añade bloques de uno en uno.
  4. Para deshacer un cambio: /undo en OpenCode o git restore archivo.
  5. Para volver a un commit anterior: usa Git.

Ocho ideas clave

  1. Un agente actúa. No es un chat: puede leer, editar y ejecutar con tu autoridad.
  2. Los permisos son tu contrato. Por defecto la V2 permite casi todo; configúralos antes de trabajar.
  3. Pide planes antes de actuar. El agente plan explora sin editar.
  4. Comprueba siempre. Ejecuta las pruebas tú; lee el diff.
  5. Git es tu red de seguridad. Commit antes de cambios grandes; commit después de verificar.
  6. Un error de formato se ignora en silencio. Si la configuración no hace nada, sospecha del archivo.
  7. No uses --auto mientras aprendes. Aprueba solo lo que entiendas.
  8. Controla el coste. Sesiones cortas, tareas acotadas, modelos adecuados y opencode stats.

Autoevaluación

1. ¿Qué diferencia hay entre un modelo y un proveedor?

El modelo genera las respuestas; el proveedor es quien lo ofrece.

2. ¿Qué agente explora sin editar?

plan (y el subagente explore).

3. En una lista de permisos, ¿qué regla manda si varias coinciden?

La última que coincide.

4. ¿Qué hace --auto y por qué es arriesgado?

Aprueba todo lo no denegado; el agente actúa sin preguntarte.

5. ¿Por qué no basta que el agente diga «ya funciona»?

Puede equivocarse o inventar; hay que ejecutar pruebas y leer el diff.

6. ¿Qué comando muestra qué configuración lee OpenCode?

opencode debug config.

7. ¿Qué pasa si tu opencode.jsonc tiene una coma mal puesta?

Puede ignorarse en silencio: no aparece en debug config.

8. ¿Qué es .gitignore y para qué lo usas con claves?

Lista de archivos que Git no guarda; evita subir secretos.

9. ¿Qué no deshacen las instantáneas de OpenCode?

Efectos de comandos (procesos, bases de datos, commits); no son copia de seguridad.

10. ¿Quién publica una web en GitHub Pages: OpenCode o GitHub?

GitHub; OpenCode solo escribe el código.
